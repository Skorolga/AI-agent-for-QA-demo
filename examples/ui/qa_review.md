# QA Review — demo

## Сильные стороны

- критический путь формы покрыт;
- есть негативные сценарии;
- присутствует traceability;
- выделены automation candidates.

## Что уточнить

- форматы телефона;
- поведение формы после успеха;
- подтверждение создания заявки на backend;
- способ эмуляции ошибки сервера.

## Рекомендации

- добавить конкретные тестовые данные;
- закрепить правила валидации;
- добавить accessibility smoke;
- использовать отдельный mock/stub для error scenarios.
